1. Platform Overview

What is Galecto?

Galecto is an enterprise-grade observability platform that combines:

  • Distributed Tracing - Track requests across services
  • Log Aggregation - Search and analyze logs
  • Metrics & Monitoring - Real-time system health
  • Alert Management - Incident tracking with SLA
  • Replay Feature - Reproduce issues for debugging
  • SLO Tracking - Monitor service level objectives

Architecture

ServicePortPurpose
Frontend3000Web UI
API Gateway3001Ingress, Replay, OTLP
Auth Service4000Authentication, RBAC
Log Service4001Kafka → ClickHouse
Query Service4002Traces, Logs, Metrics
Alert Service5003Alert Detection

Technology Stack

  • Frontend: Next.js, React, Tailwind CSS
  • Backend: Fastify (Node.js)
  • Database: PostgreSQL (metadata), ClickHouse (telemetry)
  • Message Queue: Kafka
  • Caching: Redis

2. Getting Started

Prerequisites

  • Node.js 20+
  • PostgreSQL (running on localhost:5432)
  • Redis (running on localhost:6379)
  • Kafka (running on localhost:9092)
  • ClickHouse (running on localhost:8123)

Installation Steps

Step 1: Clone & Install

git clone <repo-url> galecto
cd galecto
npm install

Step 2: Setup Database

cd apps/auth-service
npx prisma generate
npx prisma db push

Step 3: Start Services

cd ../..
npm run dev:all

Step 4: Access Platform

Open browser: http://localhost:3000

First Time: Register a new account - it will automatically create your organization, default project, and API key.

5. Traces & Causality

View Traces

Go to: http://localhost:3000/traces

Features:

  • List of recent traces with timestamps
  • Click any trace to see causality tree
  • View span relationships (parent-child)
  • Filter by service

Causality Tree

Each trace shows as a tree structure:

  • Root Span - Entry point
  • Child Spans - Downstream calls
  • Duration - Time taken
  • Status - Success/Error

Anomalies

View error traces: /api/v1/traces/anomalies

Filter by:

  • Error status (4xx, 5xx)
  • High latency (>500ms)
  • Service name
Trace ID: Each request gets unique trace_id for tracking across services.

9. Replay Feature

What is Replay?

Replay allows you to reproduce a past request to verify fixes without affecting production.

How to Use

  1. Go to Traces page
  2. Select a trace
  3. Click "Run Replay"
  4. System reconstructs the request
  5. Executes in controlled environment

Safety Features

  • PII Masking - Masks sensitive data
  • Header Filtering - Removes auth tokens
  • URL Allowlist - Only localhost/staging allowed
  • Redaction - Removes passwords/secrets

View Replay History

API: GET /api/v1/replays

Important: Replay executes real requests. Ensure target environment is test/staging.

11. API Keys

Generate API Key

  1. Go to Settings → Projects
  2. Select project
  3. Click "+ New Key"
  4. Enter key name
  5. Set expiry (optional)
  6. Define scope (ingest/read/write)

Key Scopes

ScopePurpose
ingestSend telemetry data
readQuery traces/logs
writeCreate resources

Key Rotation

To rotate a key (without downtime):

  1. Create new key
  2. Update applications to use new key
  3. Revoke old key

API: Key Operations

POST /projects/keys/:id/rotate   # Rotate key
POST /projects/keys/:id/revoke    # Revoke key
GET  /projects/keys/audit-logs     # View history
Security: Keys are shown only once at creation. Store securely!

14. SLOs & Burn Rate

What is SLO?

Service Level Objective - Target metrics for your service.

Create SLO

  1. Define indicator type:
    • error_rate - Percentage of failed requests
    • latency - Response time threshold
    • availability - Uptime percentage
  2. Set target percentage (e.g., 99.9%)
  3. Choose time window (default: 7 days)

Monitor SLO Status

View: GET /api/v1/slo-status

SLO Status Fields:

  • totalRequests - Total requests in window
  • errorCount - Number of errors
  • successRate - Percentage successful
  • meetsErrorSlo - Boolean (error threshold met)
  • meetsLatencySlo - Boolean (latency threshold met)
Burn Rate: How fast you're consuming your error budget. High burn rate = alert!

17. OTLP Integration

OpenTelemetry Support

Galecto supports OTLP protocol for:

  • Traces - Distributed tracing data
  • Metrics - Custom metrics
  • Logs - Structured logs

Endpoints

Data TypeEndpoint
TracesPOST /v1/traces
MetricsPOST /v1/metrics
LogsPOST /v1/logs

Authentication

Use API key in Authorization header:

Authorization: Bearer YOUR_API_KEY

Example: Send Traces

curl -X POST http://localhost:3001/v1/traces \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"resourceSpans":[{"scopeSpans":[{"spans":[{"traceId":"...","name":"test"}]}]}]}'
Compatible with: OpenTelemetry SDKs, Jaeger exporters, Prometheus (metrics), Fluentd (logs)

19. Troubleshooting

Common Issues

1. Services Won't Start

Solution: Check dependencies are running 
# Check PostgreSQL
pg_isready -h localhost -p 5432

# Check Redis
redis-cli ping

# Check Kafka
kafka-topics --list --bootstrap-server localhost:9092

2. Database Connection Error

Solution: Verify DATABASE_URL in .env 
DATABASE_URL="postgresql://postgres:password@localhost:5432/postgres"

3. JWT Token Expired

Solution: Re-login to get new token 
POST /auth/login with credentials

4. API Key Not Working

Solution:
  • Check key is not revoked
  • Verify key is not expired
  • Ensure correct scope enabled

5. No Data in Traces/Logs

Solution:
  1. Check Kafka is running
  2. Verify ingest endpoint receiving data
  3. Check ClickHouse has data: SELECT COUNT(*) FROM events

6. Alert Service Not Working

Solution:
  • Check alert-service is running
  • Verify Kafka consumer is active
  • Check logs: docker logs alert-service

Run Tests

# Install Playwright
npx playwright install --with-deps chromium

# Run integration tests
npm run test:integration

View Logs

# All services
npm run dev:all

# Individual service
cd apps/auth-service
npm run dev
Pro Tip: Check the GitHub Actions CI pipeline for automated testing results!
